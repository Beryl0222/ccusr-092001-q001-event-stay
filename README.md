# 赛事停留链路协调

面向职业联赛与群众赛事的城市接待协调后端：把**赛事场次、最小化保存的观众行程意向、接驳班次、住宿容量、主题线路**编排成可追踪的停留链路，回答各时段接待缺口、生成不超载的推荐方案，并在赛程改期、场地临时关闭、合作方迟报时自动产出带原因与影响范围的改线建议，留待人工确认。

`domain.json` 保存参与方、事件与数据边界的基础约定，服务中的岗位、事件名均沿用其中称谓。

## 设计要点

- **事件溯源（唯一事实源）**：所有变更只追加到 JSONL 事件日志（`data/eventlog.jsonl`），内存状态完全由事件重放得到。事件以哈希链（`sha256(前哈希|序号|类型|规范化载荷)`）串联，日志被篡改或缺行时启动即失败。
- **确定性结果**：编排是纯函数——候选资源按标识排序、按固定次序贪心分配、时间一律使用当地民用时间（`2006-01-02T15:04:05`）。同一事件序列在重放或重启后产出逐字节一致的缺口报告、推荐方案与改线建议。
- **缺口报告 = 推荐方案的聚合视图**：两者共用同一次分配，报告给出每时段的需求/已承接/有效供给/缺口，绝不会出现“方案已满足、报告却报缺口”。方案宁可显式列出“未满足”，也**绝不超载**。
- **自动改线工作流**：场次改期、场地临时关闭、合作方暂停、容量迟报都会先固定扰动前方案快照，事件应用后重算；仅当方案签名（内容哈希）变化时生成《改线建议》，内含原因、原因类别、触发事件序号、影响范围（场次/观众/班次/合作方/场馆）、原方案与建议方案。建议默认“待确认”，人工确认/驳回的决定人与意见永久留痕，重复决定返回 409。
- **最小化个人数据**：观众行程只保存化名标识、人数、时间与服务选择（是否接驳、入住/退房日期、线路选择），不存姓名、证件号、联系方式。同一“观众标识+场次”的重复提交必须带递增修订号；所有写命令支持 `Idempotency-Key`，重试返回首次结果而不重复落事件。
- **岗位鉴权与查询审计**：Bearer 令牌映射五类岗位与最小作用域；个人行程的查询仅“赛事运营”可执行，每次查询写入《查询审计》事件（岗位、条件、返回条数）。聚合缺口不含个人标识，协同岗位可读；逐条推荐方案属于个人行程，仅运营可读。

承载等级安全系数：**甲 100% / 乙 85% / 丙 70%**（基础容量乘系数向下取整）；场地临时关闭时窗内有效容量为 0。交通时窗之外的班次不参与编排。住宿按当地日期逐夜计需（入住当晚至退房前一晚，跨日自然展开）。

## 运行

```bash
go run . -check           # 核对 domain.json 与事件日志完整性
go test ./...             # 全部单元/场景测试
go run . -addr :8000      # 启动服务，事件日志默认 data/eventlog.jsonl
                          # -store /path/log.jsonl 指定日志；:memory: 为纯内存
                          # -auth tokens.json 替换内置联调令牌（{"令牌":"岗位"}）
curl localhost:8000/health
```

内置联调令牌（仅用于开发，生产请用 `-auth` 替换）：

| 岗位 | 令牌 | 主要作用域 |
| --- | --- | --- |
| 赛事运营 | `ops-2026` | 赛程发布/改期、方案确认、行程提交与查询、推荐、事件回放 |
| 交通协调 | `traffic-2026` | 交通时窗、接驳班次、聚合缺口 |
| 场馆值守 | `venue-2026` | 场馆登记、临时关闭/解除、聚合缺口 |
| 住宿合作方 | `lodging-2026` | 合作方状态、容量快照（迟报自动标记）、聚合缺口 |
| 文旅调度 | `tourism-2026` | 主题线路编排、聚合缺口 |

## 接口一览

除 `/health` 外均需 `Authorization: Bearer <令牌>`；写命令建议带 `Idempotency-Key`。

| 方法与路径 | 岗位 | 说明 |
| --- | --- | --- |
| `POST /v1/venues` | 场馆值守 | 登记场馆（等级 甲/乙/丙、基础容量） |
| `POST /v1/partners` | 住宿合作方 | 登记/更新合作方与状态（正常/暂停、报送截止） |
| `POST /v1/capacities` | 住宿合作方 | 容量快照；晚于报送截止自动标“迟报”并触发改线 |
| `POST /v1/windows` | 交通协调 | 按日设定交通时窗 |
| `POST /v1/shuttles` · `POST /v1/shuttles/{id}/adjust` | 交通协调 | 接驳班次计划/调整 |
| `POST /v1/routes` | 文旅调度 | 主题线路与日容量 |
| `POST /v1/matches` | 赛事运营 | 赛程发布 |
| `POST /v1/matches/{id}/reschedule` | 赛事运营 | 场次改期，必要时生成改线建议 |
| `POST /v1/closures` · `POST /v1/closures/{id}/end` | 场馆值守 | 临时关闭/解除 |
| `POST /v1/intents` | 赛事运营 | 提交/修订最小化行程意向（修订号递增） |
| `GET  /v1/intents?match=M1[&观众标识=A]` | 赛事运营 | 个人行程查询，**每次写审计事件** |
| `GET  /v1/matches/{id}/gaps` | 全部协同岗位 | 各时段接待缺口（聚合，无个人标识） |
| `GET  /v1/matches/{id}/recommendation` | 赛事运营 | 不超载推荐方案（逐条编排） |
| `GET  /v1/proposals` · `GET /v1/proposals/{id}` | 赛事运营 | 改线建议列表/详情（含原方案与建议方案） |
| `POST /v1/proposals/{id}/decision` | 赛事运营 | 人工“确认/驳回”，带意见 |
| `GET  /v1/events` | 赛事运营 | 事件日志回放（巡检/追责） |

## 快速体验

```bash
# 1) 登记场馆与合作方
curl -s -H "Authorization: Bearer venue-2026" -H 'Content-Type: application/json' \
  -d '{"场馆":"V1","名称":"市体育中心","等级":"乙","基础容量":1000}' localhost:8000/v1/venues
curl -s -H "Authorization: Bearer lodging-2026" -H 'Content-Type: application/json' \
  -d '{"合作方":"H1","类型":"住宿","状态":"正常","报送截止":"2026-09-20"}' \
  localhost:8000/v1/partners
# 2) 发布场次、班次、容量、跨日行程意向后：
curl -s -H "Authorization: Bearer traffic-2026" localhost:8000/v1/matches/M1/gaps
# 3) 改期后查看自动改线建议并人工确认
curl -s -H "Authorization: Bearer ops-2026" -H 'Content-Type: application/json' \
  -d '{"决定":"确认","意见":"加开备用班次后执行"}' \
  localhost:8000/v1/proposals/chg-000001/decision
```

## 代码结构

| 文件 | 职责 |
| --- | --- |
| `events.go` | 事件信封、哈希链、内存/JSONL 文件存储与启动校验 |
| `domain.go` | 领域模型、状态聚合与事件应用（apply） |
| `planner.go` | 确定性编排：不超载方案与缺口聚合（同一分配） |
| `service.go` | 命令处理、幂等、改期/关闭/迟报/暂停的自动改线与人工确认 |
| `api.go` | HTTP 路由、岗位令牌鉴权、行程查询审计 |
| `main.go` | 装配、`-check` 巡检、令牌文件加载 |
| `service_test.go` | 等级系数、重复提交、跨日、超载、改期、关闭、迟报、暂停、权限、重放/重启一致性 |
